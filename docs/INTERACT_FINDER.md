# 交互发现器（interact_finder）—— 用法与适用范围

> 这是 BAEI 项目里**唯一**既有正结果、又补上了匹配对照的机制，做成了一个可以直接跑的命令。
> 它不是学习器、不是通用架构：它做一件事 —— **在一族候选交互里，从读出自己的残差里选出该有的那一处。**

---

## 它解决什么

给你一条流，其中目标 = **两个相隔若干步的变量之间的一个交互**（不是任一个单独的变量）。
统计捷径（只看单个变量的模型）在这种任务上有个**手算下界** `log2(K)` 比特；
而**加上正确的那一处交互，残差直接归零**。

判据不需要标签以外的任何东西：拟合一个加性读出 → 用它的**残差**去关联每一个候选联合块 →
分数最高的那个就是它。加进去，重拟合。

## 怎么跑

```powershell
# 部件自检 + 一次完整对照（基线 / 判据排名 / 加上选中 / 加上正确 / 加上错误的 / 置换零分布）
.\.venv\Scripts\python.exe tools\diagnostics\interact_finder.py --mode demo --K 8,32 --cands 20,100 --samples 20000,80000

# 适用范围扫描（K × 候选数 × 样本量）
.\.venv\Scripts\python.exe tools\diagnostics\interact_finder.py --mode envelope --K 8,32,64,128 --cands 20,100 --samples 20000,80000 --seeds 2
```

每次运行先跑 `_self_check()`：把"不物化 K² 矩阵"的快速判据与 §286 的物化中心化形式**数值对齐**
（当前最大相对误差 4e-16）。判据写错时它会当场炸，而不是安静地给出一个排名
—— 它确实抓到过一次（我漏掉了一个非零的列和项，误差 1–9%，并且会改变排名）。

## 读数怎么解读

| 列 | 含义 | 期望 |
|---|---|---|
| `bar` | 手算下界 `log2(K)` | 加性模型的极限 |
| `base` | 加性读出的实测比特 | 应当 ≈ `bar`（对上了才说明台子是对的） |
| `rank` | **判据把正确滞后排第几** | 1 = 选中 |
| `+pick` | 加上判据自己选的那块 | 越接近 0 越好 |
| `+oracle` | 加上正确的滞后（上界） | ≈ `+pick` 才说明判据没选错 |
| `wrong` | 加上一个同规模但结构错误的块 | 应当 ≈ `bar`（什么都没买到） |
| `pick_z` | 置换成对后的零分布 z | 越大越可信 |

## 适用范围（实测，不是估计）

```
   K    格子数 K²   每格训练样本    判据选中      加上选中后剩下的比特（bar 的百分比）
   8        64          89          2/2         0.0000 / 3.00   = 0%
  32      1024         5.6          2/2         0.12   / 5.00   = 2.5%
  32      1024         1.4          2/2         2.20   / 5.00   = 44%
  64      4096         1.4          2/2         2.46   / 6.00   = 41%
  64      4096         0.35         2/2         5.57   / 6.00   = 93%
 128     16384          —           SKIPPED     闭式解的宽度爆掉（K²+K·W+1 = 17665 > 预算）
```

**两条概括（很重要，它们是两个不同的限制）**：

1. **选择是稳的**：12/12 格判据都排到 #1，**连每格只有 0.35 个样本时也命中**
   ⇒ 它**始终能告诉你缺的是哪一处交互**（这本身就是一个诊断能力）。
2. **兑现由"每格样本数"决定**（不是由 K 本身）：
   ≥ ~5 个样本/格 ⇒ 几乎精确；≈1.4 ⇒ 只吃掉一半；≤0.35 ⇒ 基本没用。
   经验规则：**要兑现，训练样本数 ≳ 10 × K²。**
3. **另有一道工程墙**：闭式读出要解的方程组宽度是 `K² + K·W + 1`，成本 O(宽度³)
   ⇒ K=128 就该换稀疏/迭代求解器（一天的活），否则只在 K ≤ 64 可用。

## 什么时候**不要**用它

- **统计捷径够用的任务**：项目量过五行全负（§0.1）。任何"看前 2–3 个符号就够"的任务，
  简单基线就赢。用它之前先问："一个 n-gram / GBDT 是不是已经做到了？"
- **每格样本不足**：见上面的规则。样本不够时它仍能**指出**交互在哪，但兑现不了。
- **真实语料**：项目量过，"需要具体记忆"的位置只占 **0.24%、值 0.02–0.04 bits**（§294），
  且符号随内容翻转（§296）。它适合的是**构造出来的长程依赖任务**，不是随便一段文本。

## 状态

- 对照齐全：19 个同规模错误结构 + 3 个打乱配对的控制全部停在手算下界（§325）。
- 读出是**闭式**的（岭回归 + 内部标定温度）⇒ "头没训到位"那条批评在这条谱系上不适用。
- **没做**：真实数据任务上的端到端、流式化、以及"别人拿去用会不会踩坑"的检验。

## 与通用学习器对照（`--mode vs-gbdt`）

```powershell
.\.venv\Scripts\python.exe tools\diagnostics\interact_finder.py --mode vs-gbdt --K 8,32 --samples 20000,80000 --rounds 60
```

它先跑**仪器检查**（在纯加性任务上，基线必须到 ~0——不通过就把下面的读数标成无效），然后并排报：

| 臂 | 在 K=8 / 20000 上的读数 |
|---|---|
| 加性（只用单个变量） | 2.9999 bits（≈ 手算下界 3.0） |
| **+ 判据自己选的一块交叉** | **−0.0000 bits，准确率 1.0000** |
| + 正确的交叉（上界） | −0.0000 |
| + **全部** W 块交叉（W·K² 列） | 0.0655 |
| **depth-2 梯度提升树**（同一份输入，60 轮 → 300 轮） | 2.61 → 2.04 bits，准确率 0.28 → 0.46 |

**读法**：提升树在大预算下确实在爬，但在**同等预算**下远达不到精确；而穷举交叉能达到、代价是 W 倍的特征宽度。
⇒ **判据的卖点不是"更便宜"，是"只挑一个就够"。**

## 与低秩交互模型（FM）对照（`--mode vs-all`）

```powershell
.\.venv\Scripts\python.exe tools\diagnostics\interact_finder.py --mode vs-all --K 8 --samples 20000,80000 --rounds 300 --dim 8 --epochs 300
```

| 同一份输入，K=8 | 20000 样本 | 80000 样本 | 宽度（列） |
|---|---|---|---|
| 加性 | 2.9999 | 3.0002 | 80 |
| **判据 + 它选的一块** | **−0.0000** | **−0.0000** | 144 |
| + 全部 10 块交叉 | 0.0655 | −0.0000 | 1361 |
| 提升树（300 轮） | 2.0356 / acc .46 | 1.7488 / acc .60 | 80 |
| **FM（低秩成对，dim 8）** | 1.0856 / acc .84 | **0.0000 / acc 1.00** | 144 |

**读法（这决定了要不要改参数化）**：
- **FM 能追平，但要 4 倍数据**（80k 才精确，判据 20k 就精确）⇒ 判据的优势是**样本效率**，不是表达能力；
- 在 **K=32** 上 FM 直接崩（10.15 bits / acc 0.09，比 5.0 的下界还差），判据是 0.13 bits
  ⇒ 判据的第二个优势是**优化稳健性**（它从残差**算出**该加什么，而不是靠梯度**学**出来）。
- ⇒ **底层要改的是交互的参数化**（K² 表 → 低秩），**不是判据**：正确组合是
  **用残差相关选出字段对 + 用低秩参数化它 + 尽量闭式拟合**。

# 更新（§331–§353）：新工具、新范围、以及**它不买精度**这件事

> 上面的正文是 §327 时刻写的。之后 26 节把范围推到了码本尺度，也**推翻了几条曾经写在这里的乐观说法**。
> 本节是必须一起读的更正。

## 新增的模式

| 模式 | 作用 | 关键读数出处 |
|---|---|---|
| `--mode emit` | **出口**：把低秩因子还原成交互表 `g(a,b)`，逐格可核对 | §340（exact = 1.0000） |
| `--mode real` | 真实字节流 + 按构造注入的交互；`--rare R` 造"证据稀有"的形态 | §340 / §341 |
| `--mode natural` | **零注入**，目标 = 语料的真实下一个字节 | §342（45 候选里排 1~3） |
| `--mode fields` | **字段级特征交叉**：记录 = 词块，字段 = 块内位置 | §343 / §344 |
| `--mode tune` | 给对手**预算曲线**（不只默认点） | §345 |
| `--mode gbm` | **真实 LightGBM** 对照 | §346 |
| `--mode pool` | 候选池 45 → 1000 | §338 |

## 范围刷新（引用请用这一行）

```
字母表 K：8 → 128（低秩 + ALS）→ 256 / 1024（嵌入 backbone + 逐值正规方程，可扩到 10⁶）
交互数 M：1 → 8（一交互一头）
候选池 ：45 → 1035
码本尺度：K=1024 ⇒ 判据 1/190、OURS = ORACLE 逐位相同、参数 28,673（精确 K² 表每对约 200 万）
操作规则：n ≳ 20·K²（必要不充分；还要看证据落在哪些格子上 ⇒ 证据稀有必须按计数加权）
```

## 三条必须写下的更正（都对"我们更优"不利）

```
① **§346：真实 LightGBM 追平。** 一度写过的"1035 候选时比对手好 100~370 倍"，
   是打**我手写的** FM/GBDT 得到的；真实 LightGBM 在同一格只差 **0.0038 bits**（我手写的留 0.16）。
   ⇒ 引用任何倍数前，先确认对手是**真的那个**，并给它**预算曲线**。
② **§350：梯度门控本来就带选择。** L1 加在门上就是选择机制 —— 它 190 个候选只开 1 个门、
   且开在真对上。⇒ "判据会选择而对手不会"是错的（教训 188）。
③ **§347：真实表格数据上没有货。** 最好的字段对只值 0.002~0.012 bits；
   判据在 German Credit 排 34/78、Adult 排 23/28。⇒ 它的假设类（一处主导的成对交互）
   在真实表格数据上**通常不成立**。
```

## 它唯一赢的那一格（§351 / §353）

```
**大字母表 + 硬预算**（= 声学码本 k-means 1024 + 端侧参数量上限的形状）：
   稠密给每个候选配因子要 195,841（K=64）/ 391,681（K=1024）个参数 ⇒ **装不进去**；
   判据路线只要 2,305 / 28,673，**在 K=128/256/1024 上 PR1 全部成立**（对 FM +0.198/+0.229/+0.29 bits），
   且**与 ORACLE 逐位相同**、同参数量的随机对**什么都没买到**。
```

## 一句话定位（更新）

> **它是一个零超参、O(n)/候选、能说出"该长出哪一处"的结构选择器；
> 它的价值是"便宜 + 可命名"，并且在"大字母表 + 硬预算"这一格才买到精度。**
> 什么时候**不要**用它，见本仓库 [`../README.md`](../README.md) 里「什么时候**不要**用它」那一节（比本文档更全）。
