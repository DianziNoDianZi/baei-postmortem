## 一句话结论

我押的命题 ——「**自己长出来的结构，能换来固定结构拿不到的东西**」—— **被自己的匹配对照否证**：

- **生长 = 容量**：从 200 个单元长到 650 个，涨了 **+0.286 bit**，其中 **+0.274 是容量、+0.012 是"过程"**（实测 0 或负）；
- **容量配平之后**：大容量生长 vs 大容量静态，**Δ = −0.031，p = 1.0**；
- **最狠的一格**：一个**随机接线、冻住的 26 节点图 + 训到位的读出层 = 0.750**，**高于所有会长大的配置**；
- 全项目**最大的单变量是一行配置**（读出步数 1500 → 6000），引擎代码**一行没改**。

细节、以及我为什么会走到这一步，见 **[`BLOG.md`](BLOG.md)**。

## 工具怎么跑

```powershell
# 依赖：numpy scipy scikit-learn（CLI 还需要 pandas；对手对照需要 lightgbm；部分模式需要 torch）
& python -m pip install numpy scipy scikit-learn pandas lightgbm

# ① 组件自检 + 一次最小的合成交互实验（会先跑内部等价性自检）
python tools/interact_finder.py --mode demo

# ② 一条命令的成品：给定 CSV + 目标列 → 判定 + 那张表
python tools/interact_cli.py --csv your_data.csv --target y
```

`interact_cli.py` 会输出：加性模型的 bits、判据挑的那一对、**全部候选对按真实留出 bits 的排名**、
随机对对照、**判据的置换零分布**，最后是一句**由数派生**的判决（通常就是"没有证据"）。

完整用法与实测范围见 **[`docs/INTERACT_FINDER.md`](docs/INTERACT_FINDER.md)**。

## 什么时候**不要**用它（这段比"怎么用"更重要）

- **真实表格数据上想找交互** ⇒ 单个字段对只值 **0.002~0.012 bit**（两个真实数据集实测）；
- **通用深度学习任务**（图像/音频/语言）⇒ 它的假设类是"少量离散成对交互"，**插不上手**；
- **候选集小、又没有硬预算** ⇒ **梯度门控（L1 加在门上）本身就是选择**，它 190 个候选只开 1 个门、且开在真对上；
- **想要精度优势** ⇒ 真实 LightGBM 在同一批字段上把差距压到 **0.0038 bit**；
- **大基数稀疏真实数据** ⇒ 加性一热逻辑回归 **≈** depth-6 GBDT（0.8473 对 0.8455）⇒ 没有交互可捡；
- **在高基数原始取值上** ⇒ 36/36 个字段对违反 `n ≳ 20·K²`（最极端一对：3190 万格子，只有 2299 个有 ≥2 行）。

**它唯一有可测优势的地方**：**大字母表（K≈1024）+ 硬参数预算**、且**恰好有一处分主导的成对交互**——
而"恰好有一处分主导交互"这个前提，在现实中找了五次都没找到。**这一格是合成的。**

## 9 条教训（速览）

① 动机制前先跑最朴素的控制 ② 先量效应量再分配努力 ③ 判据必须在跑之前写死 ④ 每个主张要有必须为 null 的对照
⑤ 任何"对手失败"的结论，先出示它在易题上的成功率 ⑥ **前提优先**（动手前写下"前提若成立该看到什么数字"）
⑦ 台子的不忠实之处跑前列出（条件熵 / 未观测变量 / 一对多） ⑧ **公理审查**（先写出你的原则禁止什么）
⑨ **来源审查**（能写成计算吗 / 能挂指标吗）

**⑥⑦⑧⑨ 是同一族：都发生在写代码之前。** 可填版本在 **[`docs/TEMPLATES.md`](docs/TEMPLATES.md)**。
